# The docfleet layout convention

This document specifies the layout on its own terms. The CLI implements and checks it, but the convention is the primary artifact: a repository that follows this document is a valid fleet whether or not `docfleet` ever runs against it.

---

## 1. Overview

A **fleet repository** is an ordinary git repository whose root holds three things: a registry file, one folder per machine, and one folder shared by every machine.

```
<repo root>/
├── fleet.json              # required — the machine registry
├── INDEX.md                # generated — table of contents
├── README.md               # created on init when missing
├── machines/               # required — one subfolder per machine
│   └── <name>/
│       ├── machine.json    # required — this machine's link declarations
│       ├── docs/           # this machine's documents
│       └── memory/         # this machine's agent memory
└── shared/                 # required — content every machine uses
    ├── commands/
    └── standards/
```

A **machine** is one physical or virtual computer, identified by a name that is unique within the fleet. A machine **owns** exactly one folder: `machines/<its own name>/`.

## 2. Ownership

| Path | Owner | Others |
| --- | --- | --- |
| `machines/<name>/**` | the machine called `<name>` — read-write | read-only |
| `shared/**` | every machine — read-write | read-write |
| `fleet.json` | every machine — read-write | read-write |
| `README.md` | every machine — read-write | read-write |
| `INDEX.md` | generated by `docfleet index`; committed by whoever ran it | read-write |
| anything else at the root | not part of the convention; treated as unowned | — |

"Read-only" means: read it as much as you like, but never commit a change to it from a machine that does not own it. `docfleet close` refuses to stage any changed path that is not `machines/<own name>/…`, `shared/…`, `fleet.json`, `README.md` or `INDEX.md`, and reports the offending paths instead of committing. A path outside all of these — say a top-level `notes/` folder someone added — is *not* writable by `close` either; the convention deliberately has no "miscellaneous" area.

Rationale: [ADR 0002 — read-only peer folders](adr/0002-read-only-peer-folders.md).

## 3. Naming rules

**Machine names** must match `^[a-z0-9][a-z0-9-]*$`: lowercase letters, digits and hyphens, starting with a letter or digit. `laptop`, `desktop`, `office-2`, `ci-runner` are valid; `Laptop`, `my_laptop`, `-spare` are not.

The restriction exists because a machine name becomes a directory name on every machine in the fleet, and case-insensitive filesystems (macOS, Windows) would otherwise let `Laptop/` and `laptop/` collide as soon as a case-sensitive machine created both. `docfleet doctor` reports a name that breaks the rule under the check id `machine-name`.

Choose names that describe the *role or location* of the machine (`laptop`, `desktop`, `office`), not its hostname or its owner. Names are permanent in practice: renaming one means moving a folder and rewriting the registry entry, and every other machine sees the rename as a delete plus an add.

**Everything else** — documents, memory files, subfolders — follows two rules only:

- Names are ASCII and contain no spaces, so that every path is quotable on every shell.
- Files starting with `.` and the literal `.gitkeep` are ignored by `docfleet index`.

## 4. `fleet.json`

Lives at the repository root. It is the registry of who belongs to the fleet.

```json
{
  "version": 1,
  "machines": [
    { "name": "laptop",  "created": "2026-01-31" },
    { "name": "desktop", "created": "2026-02-04" }
  ]
}
```

| Field | Type | Meaning |
| --- | --- | --- |
| `version` | integer | schema version; currently `1` |
| `machines` | array | registered machines, in registration order |
| `machines[].name` | string | machine name; must satisfy the naming rule and be unique |
| `machines[].created` | string | local date (`YYYY-MM-DD`) the machine was registered |

Registration order is meaningful in one place only: `INDEX.md` lists machine sections in this order.

`docfleet init --new` creates the file with an empty `machines` array and then appends the first machine. `docfleet init --join` appends to it and refuses if the name is already present. Both write it with two-space indentation and a trailing newline; keep that shape if you edit by hand, so diffs stay small.

`docfleet doctor` cross-checks this file against the folders on disk in both directions (check id `registry`): a registered machine with no folder, and a folder that is not registered, are both violations.

## 5. `machines/<name>/machine.json`

Lives in each machine's own folder and declares what that machine links.

```json
{
  "machine": "laptop",
  "links": [
    { "source": "memory", "target": "~/.myagent/memory" },
    { "source": "docs",   "target": "/opt/agent/docs" }
  ]
}
```

| Field | Type | Meaning |
| --- | --- | --- |
| `machine` | string | the machine's own name; matches the folder name |
| `links` | array | link declarations; may be empty (`init` creates it empty) |
| `links[].source` | string | a directory path **relative to this machine folder** |
| `links[].target` | string | an **absolute** path on this machine; a leading `~` is expanded |

Constraints, all validated before any filesystem change:

- `source` must be relative, non-empty, and must not escape the machine folder (`../…` is rejected). It must name a **directory that exists**, except under `--adopt`, where it may be absent or empty.
- `target` must be absolute after `~` expansion, must not resolve to a location inside the fleet repository, and must not be an existing non-directory. Two declarations may not resolve to the same target.
- Only directories are ever linked. This is a deliberate restriction — [ADR 0003](adr/0003-directory-links.md).

This file is part of the machine's own folder, so it is read-only to every other machine. Each machine's link set is its own business; nothing about `~/.myagent/memory` on the laptop is relevant to the desktop.

## 6. Machine folder contents

`docfleet init` creates two subfolders, and they carry the intended split:

| Folder | For |
| --- | --- |
| `docs/` | documents *about* this machine, written for humans and agents to read: setup notes, project state, decisions. Listed in `INDEX.md`. |
| `memory/` | the agent's own working memory, usually the target of a link. Not listed in `INDEX.md` — it is machine-generated and can be large. |

Nothing prevents you from adding more subfolders (`plan/`, `archive/`, …); only `docs/` is indexed. Empty folders are kept in git by a zero-byte `.gitkeep`, which `docfleet` writes on `init` and skips when indexing.

## 7. `shared/`

Content every machine uses. `docfleet init --new` creates two subfolders as a starting point:

| Folder | For |
| --- | --- |
| `commands/` | command or workflow definitions the agent loads on every machine |
| `standards/` | conventions that should read the same everywhere: document standards, naming rules, review checklists |

Add more as you need them. Everything directly under `shared/` is listed in `INDEX.md`.

Because every machine may write here, `shared/` is where merge conflicts actually happen. Two mitigations, both conventional rather than enforced: prefer one file per topic over one large file, and run `docfleet start` before you edit rather than after.

## 8. Suggested document tiers

The layout says *where* documents live. It says nothing about how many there should be, and a docs folder that grows without a shape becomes unreadable. A simple three-tier convention is enough, and it applies equally to `machines/<name>/docs/` and to `shared/`:

| Tier | What it is | How many | Lifetime |
| --- | --- | --- | --- |
| **0 — index** | one entry point that links to everything else and says, in a line each, what it is for | exactly one per area | permanent; updated whenever tier 1 changes |
| **1 — topic documents** | one document per topic, project or decision; the working set you actually read | as many as there are live topics | edited in place while the topic is live |
| **2 — archive** | finished, superseded or historical material, moved out of tier 1 unchanged | unbounded | never edited, only appended to |

Two rules make it work:

1. **Every tier 1 document is reachable from tier 0.** If a document is not linked from the index, it is invisible — treat it as lost. `INDEX.md` at the repository root is the fleet-wide tier 0, generated by `docfleet index`; an area may add its own local index below it.
2. **Documents move down, never sideways.** When a topic ends, move its document into the archive rather than deleting it or letting it rot in tier 1. Tier 1 should be small enough to read the file list and know what is going on.

A file that grows forever — a running log, an accumulating history — belongs in tier 2 with a rotation rule: keep a recent window in one file and split the rest by period (`history-2026-02.md`). Nothing in docfleet enforces any of this; it is a convention that keeps the repository legible after the first few hundred documents.

## 9. `INDEX.md`

Generated by `docfleet index` from the layout. It lists, for every registered machine in `fleet.json` order, the top level of that machine's `docs/`, then the top level of `shared/`:

```markdown
# Fleet index

<!-- generated by `docfleet index`; edits are overwritten -->

## machines/laptop

- [plan.md](machines/laptop/docs/plan.md)

## machines/desktop

_empty_

## shared

- [commands/](shared/commands)
- [standards/](shared/standards)
```

The output is deterministic — entries sorted by name, no timestamps, one trailing newline — so a byte comparison against a freshly generated index is a reliable staleness test. That is exactly what `docfleet doctor` does under the check id `index-stale`, and what `doctor --fix` repairs. Hand edits are overwritten; put prose in `README.md` instead.

## 10. Outside the repository

One directory lives outside the fleet repository, on each machine:

```
~/.docfleet/backup/<repo-id>/<ts>/manifest.json   # what one `docfleet link` run changed
~/.docfleet/backup/<repo-id>/<ts>/<n>/<dir>       # the directories that run displaced
```

`<repo-id>` is a 12-character digest of the repository's `origin` URL — or its absolute path when there is no origin — combined with the machine name, so several fleets and several machine identities on one computer never share a backup tree. `<ts>` is the run's local timestamp, `YYYYMMDD-HHMMSS`, with a `-1`, `-2` … suffix if two runs land in the same second. `<n>` is the index of the item within the run.

This tree is intentionally *not* in the repository: it holds the data a link displaced, which is machine-local by definition, may be large, and must survive a `git clean`. It is never pruned automatically. The manifest format and its state machine are documented in [schema.md](schema.md#manifest).

## 11. Conformance

A repository conforms to this convention when `docfleet doctor` reports no violations for every registered machine. The seven checks are:

| Check id | Fires when |
| --- | --- |
| `layout` | `fleet.json`, `machines/`, `shared/` or a `machine.json` is missing |
| `machine-name` | a machine name breaks the naming rule |
| `registry` | `fleet.json` and the folders on disk disagree, in either direction |
| `mapping` | a declared link could never be installed (bad source, bad target, duplicate) |
| `link-broken` | a declared link is missing, is not a link, or points somewhere else |
| `cross-machine` | uncommitted changes sit in another machine's folder |
| `index-stale` | `INDEX.md` is missing or no longer matches the layout |

`doctor --fix` repairs only what can be regenerated without touching data: it reinstalls links through the ordinary `docfleet link` path and rewrites `INDEX.md`. Every other finding stays report-only.
